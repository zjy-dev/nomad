## 目标

提供基于 Python 标准库的故障注入与弹性验证套件，能够对已记录的 trace 事件流实施重复、乱序、丢弃、延迟、重启和磁盘满六种故障，验证 OpenCode Session 在故障下仍保持协议一致性和状态可恢复。

## 输入与前置条件

- 冻结的合同清单：`contracts/traces/manifest.json`，版本 1.0.0。
- 每条 trace 的已记录事件序列，包含 `event_id`、`command_id`、`sequence`、`body`。
- Python 3 标准库（`unittest`、`hashlib`、`json`、`time`）。

## 交付物

- `testkit/faults/__init__.py`：导出故障模块公共符号。
- `testkit/faults/chaos.py`：核心故障注入引擎，定义 `FaultType`、`FaultConfig`、`DeliveryPlan`、`build_delivery_plan()`、`apply_delivery_plan()`、`simulate_delivery()`、`compute_event_id_hash()`。
- `testkit/faults/helpers.py`：每条故障类型的可复用测试 helper，`run_fault_injection_suite()` 与 `build_standard_fault_specs()`。
- `testkit/faults/test_faults.py`：16 条 `unittest` 用例（discover 模式下全部通过）。

## 验收条件

- [x] 六种故障类型均可独立注入，且每个 `DeliveryPlan` 的目标序号在事件序列范围内。
- [x] 丢弃/重启故障在边界序号时自动回落到有效中间序号，不产生最后一个序号的空洞。
- [x] 重复、乱序、延迟故障不破坏事件 ID 唯一性与序号单调性的断言。
- [x] 重启与磁盘满故障的最终状态为 `OutcomeUnknown` 或写拒绝，不产生部分写入。
- [x] `python3 -m unittest discover -s testkit/faults -p 'test_*.py'` 全部通过。
