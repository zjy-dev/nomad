## Decisions and deviations

- TEST-ONLY authentication: Ed25519 envelope signing/verification is a local reference. Production security requires SEC-003 Security Envelope (D-005, still Proposed).
- WebSocket is stdlib-only (no gorilla/websocket dependency). Implements RFC 6455 frame parsing with mask/unmask for client frames, ping/pong echo, and close frame handling.
- No heartbeat mechanism beyond WebSocket ping/pong — the task card's "heartbeat" is satisfied by the stdlib WebSocket frame handler.
- No capability negotiation handshake — the task card's "capability negotiation" is deferred to a future task (RL-005+). The current implementation uses a fixed protocol version (1) and rejects unknown versions.

## Security and privacy

- Fail-closed: unknown magic (`0x4E4D4401`), unsupported version (not 1), invalid signature, unregistered device → all return error responses without processing payload.
- Rate limiting prevents a single malicious device from exhausting server resources: `MaxFramesPerSecond=10` sliding window per device.
- Frame size validation (`MaxFrameSize=64KiB`) prevents memory exhaustion from oversized payloads.
- Log privacy: server logs contain only device hex IDs, frame IDs (hash prefixes), and frame counts. Payload content never appears in logs.
- WebSocket broadcast messages contain only device ID hex and frame ID — never payload content.
- No payload indexing or interpretation at the gateway layer.
