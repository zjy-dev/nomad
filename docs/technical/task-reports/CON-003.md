## Decisions and deviations

- We kept the command schemas side-by-side rather than using a discriminated union with a shared base because each variant has a distinct required field set. `additionalProperties: false` prevents silent extension by consumers.
- `OutcomeUnknown` is modeled as both a command result state and a turn event — it sits at the boundary between CON-003 and CON-001/002 contracts so the Host can mark the tool as unknown without fabricating a new durable event.

## Security and privacy

- `action_hash` is a binding cryptographic fingerprint (opaque string, max 128 chars) — no raw command content enters the contract.
- `content`/`new_content`/`permission action` fields are typed strings but are not echoed in error codes or results; they are expected to be encrypted by the Security Envelope before transport.
- Error messages are free-form but must not include prompt or code content.
