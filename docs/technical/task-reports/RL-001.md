## Outcome

Frozen the Relay module boundary, data classification, and component model as a Go stdlib + SQLite single-process reference service. The relay treats payloads as fully opaque bytes and never interprets content.

## Changed

- `relay/go.mod` — Go module definition (module `github.com/nomad/relay`, Go 1.26, `modernc.org/sqlite` for CGO-free SQLite).
- `relay/protocol.go` — Wire-level envelope (48-byte header + Ed25519 sig + payload), `DeviceID [16]byte`, `Envelope` struct with `Marshal`/`Unmarshal`/`Sign`/`Verify`/`Validate`. Constants: `MaxFrameSize=64KiB`, `MaxFramesPerSecond=10`, `MaxMailboxFrames=1000`, `DefaultFrameTTL=168h`, `ACKWindow=720h`.
- `relay/mailbox.go` — SQLite-backed `mailboxDB` with `frames`, `acks`, `devices` tables; content-hash-derived idempotency keys; WAL mode journaling.
- `relay/server.go` — HTTP server with routes: `/health`, `/v1/frame`, `/v1/frames`, `/v1/ack`, `/v1/devices/register`, `/v1/devices/deregister`, `/v1/ws` (stdlib-only WebSocket).
- `relay/worker.go` — Retention worker for periodic TTL and ACK cleanup.
- `relay/cmd/relay/main.go` — CLI entrypoint (`-db`, `-addr`, `-cleanup` flags).
- `relay/protocol_test.go` — 12 unit tests covering envelope round-trip, signature verification, payload integrity (7 opaque payload types), rate limiting, idempotent duplicates, ACK semantics, per-device isolation, TTL expiry, capacity limits, device purge, and empty payload rejection.
- `relay/server_test.go` — 6 HTTP integration tests covering register→frame→deliver→ack flow, payload integrity over HTTP with malicious payloads (SQL injection, XSS, shell commands, path traversal, binary nulls, large binary), health endpoint, worker cleanup, and rate limiting over HTTP.

## Decisions and deviations

- TEST-ONLY authentication: Ed25519 signing/verification is a local reference implementation for envelope integrity. This is NOT production E2EE. D-005 (Security Envelope) remains Proposed and must be implemented separately before production use.
- Chose `modernc.org/sqlite` (pure Go, no CGO) over `github.com/mattn/go-sqlite3` to keep the relay as a zero-CGO Go stdlib service.
- Module is a single Go package `relay` — the reference service is not split into microservices. The task card's "modular monolith" guidance is followed: one process, clear internal separation between protocol, mailbox, server, and worker layers.

## Security and privacy

- Relay treats payload bytes as opaque — never parses, interprets, or indexes content. Verified by `TestEnvelopeNeverParsesPayload` (7 payload types including binary nulls, protobuf-like, unicode) and `TestPayloadNeverParsedOverHTTP` (7 malicious payloads including SQL injection, XSS, shell commands).
- Logs contain only frame IDs (SHA-256 hash prefixes), device hex IDs, and frame counts — never full payload bytes.
- `PayloadHash()` returns SHA-256 digest truncated for privacy-safe logging (8 bytes).
- Per-device isolation: `TestDifferentDevicesIsolated` verifies cross-device ACK cannot affect another device's mailbox.
- Rate limiting: 10 frames/second per device; malicious devices cannot block others.
- Capacity: 1000 unacked frames per device; exceeded frames return `503 Service Unavailable`.

## Local run command

```text
cd relay && go run ./cmd/relay -addr 127.0.0.1:8089 -db :memory: -cleanup 1m
```

API endpoints:
- `POST /v1/devices/register` — register device with `{"device_id": "<32-hex>", "pubkey_hex": "<64-hex-Ed25519-pubkey>"}`
- `POST /v1/frame` — submit opaque frame (raw envelope bytes as request body)
- `GET /v1/frames?device=<32-hex>` — list undelivered frames for device
- `POST /v1/ack` — ACK frames with `{"device": "<32-hex>", "frame_ids": [...]}`
- `POST /v1/devices/deregister` — deregister and purge device
- `GET /health` — health check
- `GET /v1/ws?device=<32-hex>` — WebSocket for live frame notifications
