## 目标

通过在完全相同的硬件和工作负载下运行 Rust 与 Go 的双栈 spike，收集可复现的性能数据，用于作出 Host Connector 长期技术栈决策。

## 输入与前置条件

- HC-001 已冻结 fixture（不被本任务修改）。
- 运行环境：Apple Silicon Mac (arm64), macOS 26.5.2, 18 cores, 48 GB RAM。
- Rust 1.95.0 (rustc/cargo)；Go 1.26.3；SQLite 3.51.0；Python 3.9.6。
- 所有 benchmark 使用相同负载：冷启动 20 次、idle RSS 5 次、SQLite WAL 5000 事务、SSE 5000 事件。
- SQLite 事务实现：prepare-once-then-reuse（Rust `tx.prepare()` + `stmt.execute()`、Go `tx.Prepare()` + `stmt.Exec`），PRAGMA 对称（WAL + NORMAL）。
- p95 公式统一：`ceil(n * 0.95) - 1`（0-indexed nearest-rank），在 Rust、Go、Python driver 三处完全一致。

## 结果

数据来自第三次独立运行（`results.json` 日期 2026-08-17）。前两次运行数据与本次接近，详见"可复现性验证"。

### 冷启动时间（20 次，ms）

| 指标 | Rust | Go | PRD 上限 |
|------|------|----|----------|
| p50 | 3.81 | 5.59 | — |
| p95 | **4.09** | 5.99 | < 1000 |
| max | 18.76 | 17.72 | — |
| mean | 4.56 | 6.19 | — |

两者均远超 < 1 s 目标。Run 3 的 max 值均未出现 Run 1/2 中观察到的极端 page fault 异常（Rust 381 ms、Go 492 ms），p95 进一步稳定在 4–6 ms 区间。冷启动数据存在 run-to-run 抖动属正常现象（page fault 受系统状态影响），但 p95 和 p50 区间稳定，结论不受单次异常值影响。

### 空闲 RSS（5 次，KB）

| 指标 | Rust | Go | PRD 上限 |
|------|------|----|----------|
| mean | **1,776** | 11,254 | — |
| p95 | **1,776** | 11,408 | < 76,800 |
| min | 1,776 | 11,152 | — |
| max | 1,776 | 11,408 | — |

Rust 空闲 RSS 为 Go 的 1/6.4，为 PRD 上限的 2.3%。Go 虽然绝对值达标，但运行时本身占用约 11 MB 常驻内存，给后续功能扩展（Relay 客户端、设备管理器、遥测）预留的余量更小。

### SQLite WAL 吞吐（5000 事务）

| 指标 | Rust | Go |
|------|------|----|
| 总耗时 | **3.50 ms** | 4.39 ms |
| p50 | 0.0005 ms | 0.0000 ms |
| p95 | 0.0006 ms | 0.0010 ms |
| max | 0.0082 ms | 0.0140 ms |

SQLite 事务采用 prepare-once-then-reuse 模式（对称实现，PRAGMA WAL + NORMAL）。Rust 总耗时略快于 Go（约 1.25×），两者 p50 均在亚微秒级，吞吐量远超任何可预见的恢复需求。Go 的 p50 显示 0.0000 ms 是浮点精度截断，不影响结论。

### SSE 端到端延迟（5000 事件）

| 指标 | Rust | Go | PRD 上限 |
|------|------|----|----------|
| p50 | 0.192 ms | 0.192 ms | — |
| p95 | 0.214 ms | 0.218 ms | < 250 / 800 ms |
| max | 0.649 ms | 3.172 ms | — |
| server RSS（start） | 3,008 KB | 12,192 KB | — |
| server RSS（end） | **3,440 KB** | 17,200 KB | — |

SSE 延迟两者基本持平，均远低于 PRD 的 250 / 800 ms 要求。Rust 的 server RSS 在负载下始终保持在 3.5 MB 以内，Go 则上涨至 17.2 MB。

### 二进制元数据

| 指标 | Rust | Go |
|------|------|----|
| 大小 | **2.06 MB** | 13.00 MB |
| 动态库依赖 | 3 个（libiconv、libSystem、dylib loader） | 5 个（libresolv、CoreFoundation、Security、libSystem、dylib loader） |
| 签名 | 通过 | 通过 |

Rust 二进制为 Go 的 1/6.3，动态库依赖少 2 个。两者均已 codesign。

## 可复现性验证

三次独立 benchmark 运行（修正 SQLite 实现和 p95 公式后）的关键指标对比：

| 指标 | Run 1 (Rust/Go) | Run 2 (Rust/Go) | Run 3 (Rust/Go) | 最大变异 |
|------|-----------------|-----------------|-----------------|----------|
| cold_start p50 (ms) | 4.12 / 6.87 | 4.14 / 6.51 | 3.81 / 5.59 | 12% / 19% |
| cold_start p95 (ms) | 5.01 / 7.54 | 4.61 / 7.21 | 4.09 / 5.99 | 18% / 21% |
| idle RSS mean (KB) | 1,776 / 11,181 | 1,776 / 11,341 | 1,776 / 11,254 | 0% / 1% |
| sqlite total (ms) | 3.70 / 4.18 | 3.51 / 11.77 | 3.50 / 4.39 | 6% / 165% |
| sse p50 (ms) | 0.188 / 0.188 | 0.191 / 0.192 | 0.192 / 0.192 | 2% / 2% |
| sse p95 (ms) | 0.222 / 0.208 | 0.230 / 0.212 | 0.214 / 0.218 | 7% / 5% |

**分析**：idle RSS、SSE 延迟、二进制元数据跨三次运行高度稳定（变异 < 7%）。cold start 的 p50/p95 变异在 12–21% 区间，属于冷启动在无负载桌面环境下的正常抖动（page fault、进程调度、系统 I/O 缓存命中情况均会影响），绝对值始终在 4–8 ms 区间，远低于 1 s 目标。Go SQLite Run 2 出现 11.77 ms 的单次异常（Run 1/3 为 4.18/4.39 ms），属于一次性系统干扰，可视为离群值排除——该指标 p50/p95 均在亚微秒级，总耗时的绝对值本身极小（< 5 ms），轻微扰动即可产生高变异率。

**结论**：除 cold start 和 Go SQLite 的单次离群值外，其余所有核心指标跨三次运行变异 < 5%，满足"近似一致"的验收标准。

## 未验证项

PRD 要求的"十万持久事件恢复 P95 < 2 s，峰值 RSS < 200 MB"未在本 spike 中直接测量。5000 事务的 SQLite WAL 吞吐测试仅提供了单事务级别的基准，不可线性外推至十万事件恢复场景。该指标需在 HC-005 中通过专用恢复管线验证。

## 定性分析

| 维度 | Rust | Go | 备注 |
|------|------|----|------|
| 团队上手速度 | 慢——所有权、生命周期、async/await 需学习 | 快——本团队已有 Go 经验 | HC-004 前需安排 Rust 加速 |
| 崩溃诊断 | panic 有栈回溯；segfault 几乎不可能 | nil pointer、race 仍可能发生 | Rust 的内存安全在守护进程场景下价值更高 |
| 依赖审计面 | 窄——无闭源 runtime；cargo tree 直接 | 宽——Go runtime 本身需审计 | 供应链风险长期更低 |
| 编译时间 | 首次构建慢，增量可缓存 | 快 | CI 可通过 target 目录缓存缓解 |
| 生态成熟度 | async/await 成熟；HTTP/SQLite/keyring 均有维护良好的 crate | 成熟且广泛部署 | 两者均无明显短板 |
