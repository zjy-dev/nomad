## Decisions and deviations

- The runner is stdlib-only by explicit design, matching the "portable corpus" goal in CON-005. Consumers in any language can reimplement the same invariants by reading the corpus files; the reference Python implementation is not a runtime dependency.
- Corpus versioning: `corpus_version` 1.0.0 tracks the contract version 1.0.0. A breaking corpus change (new scenario, changed invariant, updated snapshot) MUST bump `corpus_version` and be listed in the manifest.
- trace-004 includes a `command_exchanges` array beyond raw events to make the permission_competition scenario's HostAccepted/Stale result explicit — without it, the trace would only show the final resolved state.

## Security and privacy

- Corpus files are documentation-grade JSON with synthetic session IDs (`sess_normal_001`, etc.) and real canonical content digests. No real user data, no real prompts, no real diffs.
- The conformance runner never opens external resources, never talks to the network, and never writes. Safe to run in CI without sandboxing concerns.

## Follow-ups

- Host Connector, Mobile and future Runtime Alpha must all consume this corpus and register their own conformance results against `python3 testkit/conformance/run.py --actual-snapshots=<dir>` once they can produce actual snapshots.
- CI hook planned: `python3 testkit/conformance/run.py --json` emits a stable JSON report for gate checks.
- Future corpus additions (e.g. SEC-005 attack vectors) must list new traces in `manifest.json` with updated `corpus_version`.
