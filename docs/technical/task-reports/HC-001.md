# HC-001 — OpenCode Connector Fixture Setup

**Status**: Complete
**Date**: 2026-08-17
**Component**: `connector/`

## Background

The Nomad connector needs a reproducible, auditable set of fixtures against which the OpenCode adapter can be developed and tested. Two fixture strategies were considered:

- **Captured**: payloads observed from a live OpenCode v1.18.16 instance
- **Synthetic**: payloads constructed from the published TypeScript type definitions and endpoint table

No live OpenCode v1.18.16 server was available at setup time. All fixtures are therefore synthetic. The `captured/` directory does not exist.

## Goal

1. Pin the upstream OpenCode version and commit
2. Snapshot the upstream API surface (endpoints + types)
3. Create synthetic fixtures covering all 7 core targets: session, message, tool, permission, diff, abort, snapshot
4. Add SSE trace fixtures for event-record/replay testing
5. Provide a validator that fails on any drift from the pinned contract

## Deliverables

## Design decisions

1. **No captured fixtures.** The `captured/` directory was intentionally deleted. All payloads are schema-derived. If live-captured data becomes available later, it must be added under a separate task with explicit labeling.
2. **SSE trace is a disposable record/replay fixture.** It is not one of the 7 required core targets but is retained for connector event-stream tests.
3. **Loopback-only constraint.** The connector base URL is `http://127.0.0.1:4096`. Any non-loopback address must be rejected (see HC-003).
4. **Validator is merge-blocking.** `validate_fixtures.py` must pass before any fixture-related change is merged.
5. **Version pin is a gate.** Changing the pinned OpenCode version requires updating `provenance.json`, regenerating fixtures, and re-running the validator.
