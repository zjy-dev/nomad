## Outcome

Implemented the opaque mailbox with per-device ACK: frames are stored as opaque bytes with idempotent writes, per-device delivery, and per-device acknowledgement. ACK removes only the acknowledged device's delivery eligibility — other devices retain their copy. Duplicate detection uses content-hash-derived frame IDs.

## Changed

- `relay/mailbox.go` — SQLite-backed mailbox with opaque frame storage and per-device ACK.
  - `frames` table: `id` (autoinc), `device_id` (BLOB FK), `frame_id` (TEXT, unique index on `(device_id, frame_id)`), `payload` (BLOB, opaque), `flags`, `ttl`, `created_at`, `acked`.
  - `acks` table: `(device_id, frame_id, ack_at)` with composite PK for idempotent ACK tracking.
  - `StoreFrame()` — content-hash-derived idempotency key from `SHA-256(deviceID + payload + nonce + timestamp)` (first 16 hex chars). Uses `INSERT ... ON CONFLICT DO NOTHING` with `RowsAffected()` to detect duplicates deterministically. Returns `(frameID, isNew, error)`.
  - `DeliverableFrames()` — returns frames where `acked=0 AND ttl > now`, ordered by `id ASC`, limited to 100 per call.
  - `AckFrames()` — marks frames as `acked=1` and inserts into `acks` table for replay protection. Idempotent: re-ACKing same frames is a no-op.
  - `IsFrameAcked()` — checks ACK status for a specific device+frame pair.
  - `DeviceFrameCount()` — total and unacked frame counts per device.
  - `PurgeDevice()` — removes all frames, ACKs, and device registration for a device.
- `relay/protocol_test.go` — tests for mailbox semantics:
  - `TestIdempotentDuplicate` — identical envelope stored twice → second returns `isNew=false`, only 1 frame in DB.
  - `TestAckSemantics` — 3 frames stored, first 2 ACKed → only 1 deliverable remains; re-ACK is no-op; per-device count correct.
  - `TestDifferentDevicesIsolated` — deviceA's ACK doesn't affect deviceB's mailbox; cross-device ACK attempt is harmless.
  - `TestPayloadIntegrityOnDelivery` — 6 payload types (single byte, full 0xFF, 1024-byte pattern, string, protobuf-like, emoji) retrieved bytes-exact.
  - `TestEmptyPayloadRejected` — empty payload rejected with `ErrNoContent`.
  - `TestDevicePurge` — full device data removal verified.
- `relay/server_test.go` — tests for HTTP mailbox API:
  - `TestDeviceRegisterAndFrameFlow` — register → submit frame → list frames → ACK → verify 0 frames remain. Payload integrity verified through the full HTTP round-trip.
  - `TestPayloadNeverParsedOverHTTP` — 7 malicious payload types (SQL injection, XSS, shell command, path traversal, JSON command, binary null, large binary) submitted and retrieved with bytes-exact integrity.

## Decisions and deviations

- Idempotency key: derived from SHA-256 hash of deviceID + payload + nonce + timestamp (first 16 hex chars). This makes duplicate detection deterministic: same envelope → same frame ID → ON CONFLICT silently ignores.
- `RowsAffected()` from the INSERT result is used instead of wall-clock `created_at` comparison, which was race-prone (two `time.Now()` calls could produce different values).
- The task card mentions "chunk metadata" — the current implementation stores payload as a single opaque blob. Chunking support (large message split across multiple frames) is deferred to a future task.

## Security and privacy

- Payload stored as opaque BLOB — never parsed, interpreted, or indexed. Verified by `TestPayloadNeverParsedOverHTTP` with SQL injection, XSS, shell command, and binary payloads.
- Per-device ACK isolation: ACKing deviceA's frame never affects deviceB's mailbox. Verified by `TestDifferentDevicesIsolated`.
- Idempotent write protection: `UNIQUE INDEX idx_frames_idempotent ON frames(device_id, frame_id)` prevents duplicate storage even under concurrent writes.
- Idempotent ACK protection: `PRIMARY KEY (device_id, frame_id)` on `acks` table ensures re-ACK is harmless.
- Privacy-safe logs: frame IDs are hash-derived hex strings, not raw payload content.
- Database leak model: a SQLite dump contains only opaque payload bytes, frame IDs (hash prefixes), timestamps, and device registration metadata — no decryption keys or content indices.

## Follow-ups

- Chunked frame support (splitting large payloads across multiple frames) is not yet implemented.
- Seven-day TTL + all-targets-ACK retention policy: the "whichever is earlier" condition between TTL expiry and per-device ACK is already supported via the `acked=0 AND ttl > now` filter, but the multi-device coordination for "all targets ACK" requires the push delivery layer (RL-005+).

API endpoints:
- `POST /v1/frame` — submit opaque envelope (raw bytes)
- `GET /v1/frames?device=<32-hex>` — list undelivered frames, returns `[{"frame_id":"...","payload":"<hex>","flags":N,"expires":...,"created":...}]`
- `POST /v1/ack` — ACK frames: `{"device": "<32-hex>", "frame_ids": ["...", "..."]}`, returns `{"acked":N,"verified":bool}`
