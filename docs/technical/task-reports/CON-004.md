## Decisions and deviations

- `last_applied_seq == snapshot_seq` must hold for any complete snapshot; the validator enforces this directly. Partial snapshots (e.g. mid-compaction) are not part of the contract.
- `state_summary` is the reducer's reduced view; the digest must cover it entirely, so any tampering changes the digest and is caught.
- Canonical digest encoding is explicit in the schema: `json.dumps(obj, sort_keys=True, separators=(',',':'), ensure_ascii=False)` over UTF-8, with the `digest` field excluded. All 9 golden snapshots were recomputed with this rule and are enforced by QA-001.
- Retention window is expressed via the `compaction_boundary_seq` relationship rather than an explicit byte/age field, to keep the schema content-agnostic.

## Security and privacy

- `digest` is a pure content hash (no sensitive material), `state_summary` is the reduced view only; raw tool output and diff content never appear in snapshots.
- `resume_result.error_message` is a free-form human-readable string — consumers are expected to sanitize before surfacing to UI.
- Snapshot comparison uses semantic diff (`semantic_diff` in `testkit/conformance/run.py`), not byte-level comparison, so benign field ordering differences do not look like tampering.
